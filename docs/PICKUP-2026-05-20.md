## Context — what we were debugging

Three session-manager sessions for the same 4 women on different days
(Road to 3.0/3.5 Weeks 1 / Rating Session / Week 3) were getting their
rating-hub games hijacked by each other, plus one was archived in rating-hub
so it looked missing from the list.

Root cause was a layered failure:

1. None of the sessions had `booking_time` set, so
   `ensureRatingHubSession` fell back to `played_date = today` — making
   rating-hub session dates depend on sync timing.
2. Video IDs got attached to the wrong session (manual paste or fuzzy
   filename match), and a Sync click silently re-pointed
   `games.session_id` to whichever session was syncing.
3. Sessions got archived in rating-hub; archived sessions hide from the
   default "Active" filter.

### 1. Server-side ownership guard in the rating-hub webhook

**Why:** defense-in-depth. Right now the only guard is in session-manager's
sync.ts. If anyone calls the webhook directly (curl, script, an older
session-manager build) they can still hijack games.

**File:** `../rating-hub/supabase/functions/pbvision-webhook/index.ts`

**Where:** inside `importSession()` (around line 257), right before the
`games.upsert(...)` call. Lookup the existing row by
`(org_id, pbvision_video_id, session_index)`. If it exists and its
`session_id` is non-null and `!== sessionId`, return an error response
(409) so the caller knows to detach first.

Make sure not to break legitimate re-sync of the SAME session (i.e. when
the existing row's `session_id` already matches the incoming one).

**Test:** call the webhook with a vid that's currently owned by session A
but pass session B's id — should 409. Same vid with session A → still
succeeds.

After change: `supabase functions deploy pbvision-webhook --no-verify-jwt`
(see `../rating-hub/CLAUDE.md` line 156 — the `--no-verify-jwt` flag is
mandatory; without it Supabase intercepts the bearer auth and 401s).

### 4. Validate vid uniqueness in session-manager

**Files:** `src/routes/sessions.ts`

- **PATCH `/api/sessions/:id`** (line 135): if `req.body.pbvision_video_ids`
  contains a vid that's currently set on a different session's
  `pbvision_video_ids`, refuse with 409.
- **POST `/api/sessions/:id/pbvision-confirm`** (line 407): same check. The
  existing `dupSlot` check on line 433 only catches same-session dups.

Cross-session check: query `sessions` for any row WHERE
`pbvision_video_ids @> '[vid]'` AND `id != current_session_id`. Supabase's
JS client: `.from("sessions").select("id, label").contains("pbvision_video_ids", [vid]).neq("id", currentId)`.

Friendly error message: `Video ID <vid> is already attached to session
"<label>". Detach it there first.`

### 5. Loud warning in `pbvision-fetch-ids` auto-matcher

**File:** `src/routes/sessions.ts` — `pbvision-fetch-ids` handler (line 487)

### 6. Show "excluded from ratings" indicator on rating-hub session page
